# Atari 2600A PAL

[Atari systems](README.md) · [Using the bench](../bench.md)

## Run the digital bench

Select **Atari 2600 PAL** and plug in [pal-bench.a26](../../carts/pal-bench.a26)
from the cartridge browser, or pass the cartridge on the command line.
The bench also accepts unbanked 2 KiB and 4 KiB `.a26` and `.bin` images.

```sh
./c64-hw-sim --machine a2600pal carts/pal-bench.a26 --headless 5 --shot pal.png
./c64-hw-sim --machine a2600pal carts/pal-bench.a26 --headless 5 --fault A202:data7=0 --shot bad-ram.png
```

Use the pin probe or scope on A200 (6507), A202 (6532 RIOT), A201
(C011903 TIA) and CART (numbered as J200 in Atari's service manual).
`A201.2:open` lifts composite sync and `A201.9:open` lifts colour.
Arrow keys and Space control the left joystick. Tab closes GAME SELECT
and the RESET button closes the console's GAME RESET switch at the RIOT.
Use Power cycle to restart the CPU.
[Atari VCS service manual, pp. 4-46–47](https://www.atarimania.com/2600/files/vcs_domestic_field_service_manual.pdf)

The bench uses schematic positions for the digital connections and circuit
equivalents for the clock, power-on reset and pull-ups. The monitor uses an
approximate PAL palette and reads the simulated luma and sync nets. The COL
signal aliases at the scope sampling rate. RF, analogue video levels,
audio, moving objects, collisions, paddle RC timing and cartridge bank
switching remain unmodelled. The Atari bench supports manual pin faults and
probing. The fault atlas and automatic diagnosis are available on the C64
and Spectrum boards.

## Physical board target

The target is the UK-market four-switch Atari VCS (CX-2600 AP) with the PAL
C011903 TIA. C017879 Rev 6 is a candidate for the physical bench. Photographs
show more than one assembly of the Rev 6 board, so match the exact example and
component population before assigning its layout and designators. The
four-switch board photographed by Tynemouth Software has a 555 reset circuit and
no 4050 video buffer. The author reports that this changed on subsequent boards.
[CX-2600 AP identification](https://static.atariage.com/2600/faq/index.html?SystemID=2600) ·
[Board revision tracker](https://consolemods.org/wiki/User:Jft/Technical_Image_Tracker#Atari) ·
[Rev 6 teardown photographs](https://www.the-liberator.net/site-files/retro-games/hardware/Atari-2600/atari-2600-4-switch-vader-rev6-1981-stamped.htm) ·
[Four-switch PAL board photographs](https://blog.tynemouthsoftware.co.uk/2018/05/easy-atari-2600-vcs-composite-video-mods.html)

## Published readings

Atari's September 1981 PAL field service manual (C018041 Rev 1) describes the
earlier two-board CX2600. Its motherboard clock and colour procedures give the
following nominal readings. Use them as reference points for the chip signals.
Verify component designators, the reset circuit and the video mixer separately
against the four-switch PCB. The PAL schematics at AtariAge include a separate
control panel and RF modulator drawing. They have no confirmed C017879 match.
[Atari PAL service manual, pp. A-16 to A-17A](https://pdfcoffee.com/service-manual-atari-2600-pal-pdf-free.html) ·
[AtariAge PAL schematics](https://atariage.com/2600/archives/schematics_pal/index.html)

| Signal | Published reference | Digital model check |
| --- | --- | --- |
| Master oscillator at TIA pin 11 | About 3.546 MHz, 4–5 V peak-to-peak | Step the raster at 3.546894 MHz nominal |
| CPU clock input, TIA pin 4 to 6507 pin 27 | 4–5 V peak-to-peak | One CPU cycle per three TIA clocks, about 1.182298 MHz |
| CPU phase 2, 6507 pin 28 to TIA pin 26 and RIOT pin 39 | 4–5 V peak-to-peak | TIA and RIOT share CPU bus timing |
| PAL chroma oscillator at TIA pin 8 | About 4.43 MHz | Separate from the raster and CPU reference clock |

The TIA counts 228 master clocks per horizontal line, with 68 clocks in
horizontal blanking and 160 visible clocks. The cartridge sets the vertical
timing using VSYNC and VBLANK. A 312-line test program therefore takes 71,136
master clocks per frame, which works out to about 49.86 Hz. A software test can
assert this count directly from the timing signals, regardless of receiver
cropping.
[Atari Stella Programmer's Guide](https://atarihq.com/danb/files/stella.pdf) ·
[PAL timing and register notes](https://www.astro.physik.uni-potsdam.de/~mwendt/2600scene/specs.html)

## Hardware checks we can reproduce from published tests

[The missingno VCS test suite](https://github.com/ajoneil/missingno-vcs-tests)
documents checks on one black-case Australian PAL console and publishes
`*_pal_capture.png` files made from its RF output. The ordinary `_pal.png`
images are emulator renders. Use the raw captures for visual comparisons and
the test ROMs' own assertions for register and bus timing. The suite's author
marks cartridge tests that need specific mapper hardware. The board revision
and UK RF path remain unverified.

For a first digital bench, check these operations in order:

1. Watch the 6507 fetch its reset vector on cartridge addresses `$1FFC` and
   `$1FFD` and run a linear ROM. Check that RIOT RAM is visible at `$80–$FF`
   and that the timer counts while the CPU waits for WSYNC. The 6507 exposes
   13 address lines, so mask the CPU core's addresses to 13 bits at the board.
2. Use the [PAL bench cartridge](../../carts/pal-bench.a26) to check the 312-line
   frame and VSYNC transitions. The cartridge fills and checks RIOT RAM with
   two complementary address patterns. It draws 12 colour bars on success and
   alternating black and white bars on failure. The program keeps the display
   state in CPU registers, so it can report a bad RAM without using it for the
   picture. Both this cartridge and the missingno suite use `$A5` for pass and
   `$5A` for fail at RIOT RAM address `$80` when that address works.
3. Compare simulated traces with published measurements as they become
   available for a lifted cartridge address pin, a lifted RIOT data pin and
   a lifted TIA video output. The TV picture also depends on the video
   mixer and decoder.

The published service readings establish expected test points. We still need
revision-matched scope or logic-analyser captures for electrical verification
of a four-switch board, especially reset timing, luma and sync levels, and
the screen symptoms of lifted pins.

## Rebuild the diagnostic cartridge

From the repository root, use DASM to assemble [the cartridge source](../../tools/pal-bench.asm):

```sh
dasm tools/pal-bench.asm -f3 -ocarts/pal-bench.a26
```

The image is 2,048 bytes. Each frame has 3 sync lines, 45 additional blank
lines, 12 bars of 19 lines each and 36 lines of overscan.

Run the raster and fault checks from the repository root with
`python tests/a2600-pal.py ./c64-hw-sim`.
